# Decisions

- Native SwiftUI, iPhone, iOS 17 minimum. Xcode 15+ supports this SDK baseline; use a current stable Xcode compatible with your Mac and phone. The cloud host is Linux, so Apple SDK compilation and runtime layout checks are explicitly pending.
- No dependencies, accounts or network services. Swift Charts provides body-weight trends. Swift Package Manager builds the same Foundation-only core that the Xcode app target compiles, enabling meaningful Linux tests without substituting a package for the app.
- One small observable application store. All mutations copy the value state, validate it, explicitly save a single versioned SwiftData document, then publish it to views. A failed save rolls back and leaves visible actuals unchanged. No termination callback is needed. A single document intentionally trades query flexibility for an atomic personal log and straightforward full backups.
- SwiftData V1 → V2 lightweight migration adds an optional updated timestamp. The independently versioned JSON format migrates v1 (no preferences or timezone) to v2 defaults. Both migrations have tests; SwiftData tests need Xcode.
- Stable seeded exercise IDs are template-specific. Historical prescriptions are value snapshots. Editing actual results never rewrites the prescription. Latest completed normal exposures use actual completion timestamps. Partial and Light workouts cannot replace the normal baseline.
- Schedule identity is the original programme date plus template ID. Moving changes its display date, never its identity. Unrecorded past entries are shown as missed, never completed. Calendar generation continues after December; first 47 planned slots end December 31, 2026. Calendar week is anchored to programme start, not the number of attended sessions. Starting an overdue session uses the actual start date's training week.
- Local calendar dates and timezone IDs are stored separately from timestamps. Europe/Warsaw is the default; changing the calendar zone affects future sessions only. Rest timers store an absolute end timestamp and are refreshed on foregrounding.
- Normal target RIR is explicit per exercise; default compound 2, isolation 1 (editable). Intro uses 3; Light uses 4. Squat/RDL normal targets stay 2. Other equipment increments are deliberately unset until relevant. Light loads without a step provisionally round to 0.5 kg with an explicit adjustment note.
- Completed warm-ups require the same input validation but never count toward progression. Neck work has seconds and holds only. Completing a workout requires every prescribed set and neck hold; otherwise finish as partial.
- Restore is replacement, not merging. Decode and validate before confirmation; make an atomic recoverable JSON backup in Documents/Recovery before replacing SwiftData. Invalid imports leave the existing document untouched. Recovery files are accessible through Files and the Settings share interface.
- JSON timestamps use exact Foundation reference-date seconds, accepting ISO-8601 from older backups. CSV timestamps remain human-readable ISO-8601. A manual next-load override is validated and consumed on starting a normal session; Light sessions leave it pending.
- The load chart displays only completed normal exposures with the same template exercise, machine/setup, unit, set count and rep range. It shows actual load points, not an estimated strength score. Body-weight charts use only recorded weekly averages.
